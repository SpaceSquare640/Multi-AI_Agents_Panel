One Mutex<Connection> guards every write, and reads take the same lock. So a slow write blocks every read in the process, and with four agents in a group chat that is most of them.

Two options, in the order I would try them:

  1. Split the lock. A read-write lock lets concurrent readers through and only serialises writers. Smallest change, and it fixes the common case.
  2. Move to a connection pool with WAL. Readers stop blocking writers entirely, but it changes the transaction story and needs a migration.

I would start with the first and measure before considering the second.

pub struct Storage {
    conn: RwLock<Connection>,
}

impl Storage {
    pub fn sessions(&self) -> Result<Vec<Session>> {
        let conn = self.conn.read()?;   // concurrent
        query_sessions(&conn)
    }

    pub fn insert(&self, m: &Message) -> Result<()> {
        let conn = self.conn.write()?;  // exclusive
        insert_message(&conn, m)
    }
}

One caveat worth knowing before you commit to it: SQLite serialises writers anyway, so this buys concurrency on reads only. That happens to be the shape of the problem here
